# Decisions (one-line ADRs)

Format: date · decision · why · alternative rejected.

- 2026-10-12 · Repo root is this folder (`R.SaaS/`), not a nested `restaurant-saas/` dir · the folder is already the project root holding `docs/` · nesting one level deeper.
- 2026-10-12 · Source docs kept under their real filenames (`Restaurant_Billing_System_Developer_SRS.pdf` etc.), mapped in CLAUDE.md · renaming the client's files is unnecessary churn · renaming to `SRS_v1.0.pdf`.
- 2026-10-12 · Build Specification PDF is treated as authoritative detail under the Playbook · it is the most specific document and is derived from both · ignoring it (the overnight prompt didn't list it).
- 2026-10-12 · `packages/ui_kit/STYLE.md` ("House Plating · Midnight Masala": dark espresso service theme, light paper back-office theme, Fraunces + DM Sans) overrides the overnight prompt's M6 palette/fonts (Lora + Inter, cream) · it is Gagan's newer, more detailed brief and keeps the wine/saffron/cream/olive/ink family for back office · following the older one-line palette.
- 2026-10-12 · Compose Postgres is published on host port **5433** · a native Postgres already listens on 5432 on Gagan's Mac · stopping the user's Postgres.
- 2026-10-12 · Two DB roles: `rsaas_owner` (migrations, seed) and `rsaas_app` (runtime, NOBYPASSRLS, no UPDATE/DELETE on audit_events) · RLS does not apply to table owners, and append-only audit needs a role without those grants · single superuser connection.
- 2026-10-12 · RLS uses transaction-local `set_config('app.tenant_id', …, true)` and `app.platform='on'` for platform-admin requests, via a `db.tenant(...)`/`db.platform(...)` helper that wraps Prisma interactive transactions · pooled connections must not leak tenant context · session-level `SET`.
- 2026-10-12 · Prisma 6.x (not 7) · stable `url = env()` datasource + mature migrate; 7 requires driver adapters/config rewrite · Prisma 7, TypeORM.
- 2026-10-12 · NestJS 11 + zod env validation + @nestjs/throttler + argon2 (Argon2id) + otplib (TOTP) + jsonwebtoken · matches Playbook "Pantry" · passport strategies (more boilerplate for no gain).
- 2026-10-12 · Ed25519 keys are passed as one-line base64 DER (PKCS#8 private / SPKI public) · avoids multi-line PEM in env vars · PEM strings with `\n` escapes.
- 2026-10-12 · License token format: `base64url(json payload).base64url(ed25519 signature)` (compact, JWS-like, alg fixed to Ed25519) · trivially verifiable in Dart and TS without a JOSE dependency · full JWS/JWT library (alg-confusion risk, bigger dep).
- 2026-10-12 · Cloud stores pushed hub events in `sync_events` (event_id PK = exactly-once); the hub-side `SyncOutbox` lives only in SQLite · the outbox is a hub concern; the cloud needs an ingest log · a cloud `sync_outbox` table that nothing writes.
- 2026-10-12 · Discount allocation: floor share per line, last line takes the remainder; if that exceeds the last line's amount the excess moves to earlier lines with headroom · Build Spec says "last line absorbs the remainder" but a naive remainder can push a line negative (vector `excess_moves_back`) · half-up shares (can over-allocate).
- 2026-10-12 · Round-off is half-up to the nearest rupee on the full payable amount (incl. tip) → range −49…+50 paise · Playbook says "nearest rupee"; the Build Spec's parenthetical "(between 50 and 49 paise)" is ambiguous · half-down. **Confirm with client.**
- 2026-10-12 · Golden vectors are generated by an independent Python reference (`packages/core/tool/gen_golden.py`, exact fractions), not by the Dart or TS code · avoids self-confirming tests · generating expectations from the Dart implementation.
- 2026-10-12 · Package name `rsaas_core` (folder `packages/core`) · avoids confusion with `dart:core` · `core`.
- 2026-10-12 · Own 15-line UUIDv7 (`src/common/uuid.ts`) instead of the `uuid` npm package · uuid@14 is ESM-only and breaks the CommonJS Nest build/Jest · pinning an old uuid.
- 2026-10-12 · Every API request-body schema in OpenAPI is derived from the zod schema the route validates with (`apiBody()`), and fixtures are recorded from a real end-to-end run · contract cannot drift from validation; Aditya gets real shapes · hand-written DTO classes.
- 2026-10-12 · Hub uses drift **without code generation**: a `GeneratedDatabase` subclass with plain-SQL schema + `customSelect/customUpdate` · keeps drift's executor, transactions/savepoints and migrations while avoiding build_runner in a 20-day plan · generated drift tables (add later if typed queries are wanted).
- 2026-10-12 · "One live order per table" is a SQLite partial unique index; transfers are a single `UPDATE … WHERE version = ?` · the database, not app code, makes double-booking impossible, so simultaneous transfers resolve to exactly one winner · app-level locking.
- 2026-10-12 · Invoice number is issued when the bill is generated (order → billed), not at payment · the printed bill must carry its tax-invoice number; numbers come from `invoice_counters` in the same transaction and bills are never deleted, so the sequence stays gap-free · numbering at payment (a printed bill would have no number). **Confirm with client.**
- 2026-10-12 · Reversal rules: before billing the line just drops out of totals; on a billed-but-unpaid order the bill is recomputed and a `BillAdjustment(type=reversal)` records the difference; once paid only `/bills/:id/adjustments` (reason + PIN) is allowed · satisfies "paid bills never edited" and AC-05 "reversal creates adjustment" · editing paid bills.
- 2026-10-12 · Unsent lines are "removed" by reversal (reason required), not hard-deleted · SRS wants a reason + trace for every cancel · silent delete of pending lines.
- 2026-10-12 · Hub UUIDv7 is monotonic within a millisecond (12-bit counter) · lines added in one request must keep their order; found by a flaky test · random-only v7.
- 2026-10-12 · Hub PIN check verifies the cloud's Argon2id PHC strings with pointycastle (cross-checked against a node-argon2 hash in tests) · one hash format end to end · a second, weaker PIN hash for the hub.
- 2026-10-12 · Hub LAN TLS: self-signed RSA-2048 cert generated on first start (basic_utils), SHA-256 fingerprint shown in the pairing QR and pinned by clients · no CA on a restaurant LAN · plain HTTP on Wi-Fi.
- 2026-10-12 · Admin portal keeps tokens in memory only (refresh on 401; browser reload = sign in again) · no tokens in localStorage, where any XSS could read them · localStorage persistence. **Confirm the UX with Gagan.**
- 2026-10-12 · Flutter widget tests run against the recorded contract fixtures (`packages/contracts/fixtures`) through a MockClient · a contract change that breaks a screen fails CI · hand-written mock JSON in each app.
- 2026-10-12 · Riverpod 2.6 + go_router 14 (Playbook stack), `admin_web` on Dart ≥ 3.8 for null-aware map entries · known-stable APIs · Riverpod 3 migration risk overnight.
- 2026-10-13 · POS keeps its device setup (hub URL, pinned fingerprint, device token) in `flutter_secure_storage` (DPAPI on Windows, Keystore on Android) · the device token is a credential · shared_preferences in plain text.
- 2026-10-13 · `/devices/register-hub` infers the branch when the tenant has exactly one, and returns `branchCode` + `licensePublicKey` · one-branch restaurants pair without picking a branch · always require `branchId`.
- 2026-10-13 · POS `flutter build web` is a compile check only (the hub needs dart:io; the web build runs as a paired client without hub mode) · catches compile errors in CI without Windows/Android toolchains · no web build.
